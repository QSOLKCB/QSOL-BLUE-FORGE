# Executor dispatch and descriptor boundaries

This note records the PR #2 correction for dispatch-global poisoning and raw process-descriptor response forgery. It supplements `CI_SUPERVISION.md`; where earlier descriptions place proposed execution in the transport process, the process topology below is the current implementation.

## Process topology

```text
trusted test worker
  -> broker (no proposed imports; non-dumpable)
    -> transport parent (no proposed imports; non-dumpable)
      -> application child (no inherited upstream transport descriptors)
        -> persistent CPython 3.12 application subinterpreter
          -> fresh detached invocation wrapper
```

The application child remains inside the existing actor kernel namespace and aggregate cgroup. The launcher, filesystem limits, task limits, CPU/memory limits, deadlines, read-only source materialization, and descendant teardown are not relaxed.

Before creating the application subinterpreter, the child replaces fd 0 with `/dev/null`, maps fd 1 to diagnostic stderr, and closes all descriptors above 2. Replacing Python stream objects alone is not sufficient and is not the boundary. The broker and transport parent both set and verify Linux `PR_SET_DUMPABLE=0`, so a same-UID child cannot recover their writable transport descriptors through `/proc/<pid>/fd`.

The child and transport parent exchange data through two fixed-capacity anonymous memory mappings. These mappings have no backing file descriptor. Native process-shared POSIX semaphores enforce single-slot publication and memory ordering. Each slot carries a bounded length and monotonically checked request generation. The application subinterpreter receives only the existing bounded immutable request bytes, not mailbox objects, pointers, or broker descriptors. The transport parent constructs the broker response and supplies its sequence from the independently retained request.

Setup failure, child death, missing publication, malformed lengths, generation mismatch, and deadline expiry fail explicitly. There is no fallback to the old shared-stdout arrangement. Parent-death signalling and the existing namespace lifetime controls retain descendant cleanup.

## Operation selection

The persistent `_operation_globals` dispatch dictionary is removed. The private control thread selects the operation before starting proposed execution. The wrapper receives that callable, arguments, keyword arguments, and exception/string primitives as local parameters; it does not resolve `getattr_fn`, `import_module`, or other dispatch functions from its globals.

Every invocation gets a new function and empty-builtins namespace. The bounded-iteration helper is fresh as well. After the detached frame unwinds, the private control thread validates the exact namespace shape and original empty-builtins identity before consuming a result or exception. Added, replaced, or removed namespace entries fail closed. Validation checks the stored key's exact type before dictionary lookup, avoiding overloaded-key hooks in the control thread.

CLI orchestration remains separate from in-process proposed calls. The original exception-hierarchy validation, immutable case-result semantics, and golden receipt expectations remain unchanged.

## Mandatory regression controls

The baseline-owned supervisor runs the new boundary controls before the real test floor, in addition to all existing self-tests:

* An import-time frame walk attempts to replace `getattr_fn`. The real `probe()` result must remain `wrong`; an assertion expecting `real` must fail.
* An import queues marshal-framed module/getattr/call responses using `os.write(1, ...)`, then calls `os.dup2(2, 1)`. Those bytes must remain diagnostics: the real-result positive control passes and the forged-result negative control fails.
* A probe attempts to reopen the immediate transport parent's and upstream broker's stdout descriptors through `/proc`. Neither reopening is allowed.
* An unconditional mutation of the fresh invocation namespace must fail with the namespace-integrity diagnostic, not for an unrelated setup failure.

Successful controls emit `executor_dispatch_isolation=PASS executor_descriptor_isolation=PASS`. These markers are generated by the trusted supervisor after the controls, never accepted from proposed stdout.

## Contract and trust scope

The constitutional identity remains `blue-forge.core-invariants/v1`. No application evaluator, existing frozen regression test, schema, reference fixture, golden receipt, launcher, or workflow is promoted or modified by this correction. Only the reviewed supervisor and executor blobs require the existing path-limited external-baseline authorization; that baseline commit must retain the prior external baseline as its parent, not the proposed PR head.

This is regression evidence for the stated observation boundaries. Neither a process-local value, a Python audit hook, a shared-memory observation, nor a successful CI run is a universal attestation that arbitrary hostile Python behaves honestly. The existing kernel sandbox and repository governance remain required.
